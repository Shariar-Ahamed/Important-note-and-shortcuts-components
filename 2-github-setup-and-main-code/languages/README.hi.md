## 2 GitHub पर्सनल एक्सेस टोकन (PAT)

| चरण | हिन्दी विवरण |
|------|-------------|
| **Settings → Developer settings → Personal access tokens → Tokens (classic)** | नया एक्सेस टोकन जनरेट करने के लिए जाएं |
| स्कोप चुनें | सामान्य उपयोग के लिए repo, notes, admin:org चुनें |
| उदाहरण टोकन | `ghp_yourPersonalAccessTokenHere...` |

### 2.1 SSH कुंजी प्रमाणीकरण सेटअप

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `ssh-keygen -t ed25519 -C "your_email@example.com"` | एक सुरक्षित SSH कुंजी जोड़ी बनाएं |
| `eval "$(ssh-agent -s)"` | टर्मिनल में SSH एजेंट शुरू करें |
| `ssh-add ~/.ssh/id_ed25519` | प्राइवेट SSH कुंजी को एजेंट में जोड़ें |
| `cat ~/.ssh/id_ed25519.pub` | पब्लिक कुंजी दिखाएं (GitHub Settings में कॉपी करें) |
| `ssh -T git@github.com` | GitHub के साथ कनेक्शन का परीक्षण करें |
| `git remote set-url origin git@github.com:username/repo.git` | URL को HTTPS से SSH में बदलें |

## 4 बुनियादी Git कार्यप्रवाह

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git init` | नई लोकल रिपॉजिटरी शुरू करें |

## 6 हटाई गई फ़ाइलों को संभालें

> [!WARNING]
> **Force Push (`git push -f`) का प्रयोग सावधानी से करें!** यह रिमोट इतिहास को मिटा सकता है।

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git add -A` | हटाने सहित सभी बदलावों को स्टेज करें |
| `git commit -m "Updated file structure"` | हटाए गए फ़ाइलों के साथ प्रतिबद्ध करें |
| `git push -f origin main` | जबरन बल (Force Push) से अपडेट करें |

## 7 नवीनतम कोड खींचें (Pull)

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git pull origin main` | रिमोट main शाखा से नवीनतम कोड प्राप्त करें |
| `git pull` | ट्रैक की गई शाखा से अपडेट करें |
| `git pull origin main --rebase` | साफ़ इतिहास के साथ कोड खींचें |
| `git push origin main` | स्थानीय काम रिमोट पर भेजें |

## 15 ब्रांच प्रबंधन

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git branch` | सभी लोकल शाखाओं की सूची देखें |

| `git merge new-branch` | शाखा को मर्ज करें |

| `git branch -D new-branch` | जबरन शाखा हटाएं |
| `git push origin --delete branch-name` | GitHub से रिमोट शाखा हटाएं |

## 17 गलतियों को सुधारें और पूर्ववत करें

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git restore file.txt` | फ़ाइल को पिछली सहेजी स्थिति में वापस लाएं |
| `git reset HEAD file.txt` | फ़ाइल को अनस्टेज करें |
| `git commit --amend` | पिछले कमिट संदेश को संपादित करें |
| `git reset --soft HEAD~1` | अंतिम कमिट रद्द करें पर कोड रखें |
| `git reset --mixed HEAD~1` | कमिट रद्द करें और अनस्टेज करें |
| `git reset --hard HEAD~1` | अंतिम कमिट और सभी बदलावों को पूरी तरह हटाएं |
| `git revert <commit-hash>` | विपरीत कमिट बनाकर इतिहास बनाए रखें |

## 18 Stash (अस्थायी रूप से सहेजें)

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git stash` | अधूरे काम को अस्थायी रूप से छिपाएं |
| `git stash save "message"` | नाम के साथ सहेजें |
| `git stash pop` | छिपा काम वापस लाएं और स्टैश हटाएं |
| `git stash apply` | स्टैश हटाए बिना कोड लागू करें |
| `git stash list` | सभी सहेजे गए स्टैश देखें |
| `git stash drop` | विशिष्ट स्टैश हटाएं |
| `git stash clear` | सभी स्टैश साफ़ करें |

## 22 टैगिंग (संस्करण नियंत्रण)

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git tag v1.0` | संस्करण टैग बनाएं |
| `git tag -a v1.0 -m "Release v1.0"` | संदेश के साथ टैग बनाएं |
| `git tag` | सभी टैग देखें |
| `git push origin v1.0` | टैग को GitHub पर भेजें |
| `git push origin --tags` | सभी टैग भेजें |

## 23 आधुनिक Git नेविगेशन (switch & restore)

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git switch <branch-name>` | शाखा बदलें |
| `git switch -c <new-branch>` | नई शाखा बनाएं और बदलें |
| `git restore <file>` | फ़ाइल को पुनर्स्थापित करें |
| `git restore --staged <file>` | फ़ाइल अनस्टेज करें |

## 24 मर्ज संघर्षों को हल करें

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git status` | संघर्ष वाली फ़ाइलें देखें |
| फ़ाइलों को सुधारें | `<<<<<<<` और `>>>>>>>` के बीच सही कोड रखें |
| `git add <resolved-file>` | हल के रूप में चिह्नित करें |
| `git commit -m "Resolved merge conflict"` | मर्ज पूरा करें |
| `git merge --abort` | अटके मर्ज को रद्द करें |

## 25 Git Reflog – खोए हुए कोड को पुनर्प्राप्त करें

| कमांड | हिन्दी विवरण |
|---------|-------------|
| `git reflog` | सभी क्रियाओं का सुरक्षा लॉग देखें |
| `git reset --hard HEAD@{n}` | सटीक स्थिति में पुनर्प्राप्त करें |
| `git branch <recovered-branch> <commit-hash>` | हटाई गई शाखा को फिर से जीवित करें |

## 27 Cherry-Pick और इंटरेक्टिव रीबेस

|---------|-------------|

| `git rebase main` | मुख्य शाखा के साथ रीबेस करें |

## 🚀 प्रो टिप्स (Pro Tips)

- **हमेशा `git pull` चलाएं** नया काम शुरू करने से पहले।
- **वर्णनात्मक कमिट संदेश लिखें** (`fix: navbar bug`).
- **`git reflog` का उपयोग करें** यदि आपको लगता है कि कोड खो गया है!
